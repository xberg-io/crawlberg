- Almost everything in e2e/ is generated — DO NOT EDIT. The generated files are the ones carrying an `alef:hash:` provenance line in their header; that marker, not the directory, is what identifies generator-owned content
- Three files under e2e/ are HAND-WRITTEN and must never be regenerated over or deleted: `e2e/node/tests/ssrf.test.ts`, `e2e/wasm/tests/ssrf.test.ts`, `e2e/rust/tests/ssrf_test.rs` (the SSRF-defence coverage, each self-labelled in its first line). They carry no marker, so nothing automated distinguishes them from generator output — treat this list as the record. Their self-label must never contain the substring `generated by alef`: alef's ownership predicate (`core::hash::content_has_alef_marker`) is a case-insensitive substring match over the first 10 lines with no negation handling, so a comment saying "NOT generated by alef" made alef claim all three, reporting them as permanently stale and orphaned under `alef verify`
- `e2e/go/helpers_test.go`, `e2e/go/main_test.go` and `e2e/elixir/test/test_helper.exs` were previously listed as hand-written. They are not: `alef verify` reports them FROZEN, meaning they sit in alef's managed surface and alef would emit them today. They are now adopted and alef-owned. The only hand-added content that existed in them was an `Crawlberg.Native.set_env/2` call in the Elixir helper, which was dead — that function is not declared in `packages/elixir/lib/crawlberg/native.ex`, so the call always raised and was always swallowed by its own `rescue`. Change them via fixtures or generator config, not by editing them
- To change: modify fixtures or generator source, run `task e2e:generate`, run `task e2e:test`, commit together
- CI drift gate: the `e2e-tests` matrix in `.github/workflows/ci-e2e.yaml` runs `alef e2e generate --lang <lang>` and checks `git status --porcelain -uall` against that language's `e2e/` directory. **FOUR of the 16 matrix legs are excluded, not two** — `python`, `php`, `ruby` and `c` — so `ruby` and `c` generated output is NOT guarded against fixture drift by CI. The exclusions cover two distinct kinds of formatter skew, and the distinction matters when deciding whether a new language needs excluding:
  - **Formatter MISSING on the runner** (`python`, `php`): alef's format step shells out to a bare `ruff` binary (not `uv run ruff`, and ruff is not a project dependency anywhere in this repo), and for php to `packages/php/vendor/bin/php-cs-fixer`, which this job never installs. Both would emit UNformatted output against a formatted tree.
  - **Formatter PRESENT but not equivalent** (`ruby`, `c`) — the inverse failure, observed live on `9aaaf3410`. Ruby's formatter is `bundle exec rubocop`; when bundler is not set up **alef degrades to a WARN and silently skips formatting**, so committed spec files keep a form rubocop rewrites the moment it does run. For `c`, `clang-format` runs in both places but its output is version-dependent.
  - `dart` hits the same "present but not equivalent" skew and is handled by **pinning** the SDK version in the matrix so the runner's `dart format` is a fixed point of the committed tree — the better pattern, and the one to prefer for a new language.
  The real fix is pinning every formatter toolchain so generation is reproducible; the silent WARN-and-skip is an alef defect. See the `~keep` comment above the check in the workflow for the full reasoning.
- Generated-code gates in this repo FAIL OPEN, so never treat a green one as evidence that generated output is correct. `alef verify` hashes generation *inputs*, not output bytes — its own report distinguishes files that are "present but NOT content-verified", so a present-but-wrong file passes. Snapshot, `fmt --check` and `tsc` checks likewise pass on broken generated output. To prove a regeneration is clean: `alef cache clear` first (a "Generated 0 files" line is a cache report, not a result), run generation twice, and require a byte-identical `git diff | shasum`.
